The Standard Autotools Workflow (includes automake)
When you use the MinGW method to build Rufus, you are engaging with a classic Autotools pipeline, which consists of three main steps:

Step				Command									Standard Purpose
1. Generation		./bootstrap.sh (or autoreconf -f -i)	This step generates the configure script and other build files from configure.ac and Makefile.am.
2. Configuration	./configure								This script analyzes your system, checks for dependencies, and creates the platform-specific Makefiles.
3. Building			make									This reads the generated Makefile to compile the source code and link the final rufus.exe executable.

Telltale Signs of Automake
Indicator										What It Means
Makefile.am files								These are the primary input for Automake. Each directory that needs building will contain a Makefile.am.
configure.ac (or configure.in)					This is the Autoconf input file. Automake works together with Autoconf, so a configure.ac is almost always present.
aclocal.m4 and m4/ directory					These hold macro definitions for Autoconf.
autom4te.cache/ directory						A cache directory created by Autoconf; it’s often present after running autoreconf.
autogen.sh, bootstrap.sh, or autoreconf usage	Scripts that generate the configure script and Makefile.in files from Makefile.am and configure.ac.
Makefile.in files								These are generated from Makefile.am by Automake. If you see them in the repository (though often they are excluded from version control),
			 									it’s a strong sign.
configure script (generated)					A large shell script that starts with #! /bin/sh. If the repository contains it, it’s likely generated by Autoconf/Automake.
